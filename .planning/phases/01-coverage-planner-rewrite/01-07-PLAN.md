SPEC R-12 (validation pipeline) — the 10 spec validation points, mapped to error codes:
1. Footprint inside allowed area -> ERROR_FOOTPRINT_VIOLATION (failed_validation_point=1)
2. No obstacle intersections -> ERROR_FOOTPRINT_VIOLATION (failed_validation_point=2) (or OBSTACLE_BLOCKS_AREA if entire area blocked)
3. Mowing only in working areas -> ERROR_INTERNAL (failed_validation_point=3) — invariant; should never trigger if planner is correct
4. Navigation areas blade-off -> ERROR_INTERNAL (failed_validation_point=4) — invariant
5. Outline offset against robot body -> implicit in OutlineGenerator
6. Path spacing matches tool_width-overlap -> implicit in BoustrophedonSweeper
7. Narrow areas not driven -> handled by NarrowAreaStrategy; SKIP -> warning, OUTLINE_ONLY/SPECIAL_PATTERN -> handled
8. Dock segments collision-free -> ERROR_DOCK_OUTSIDE_AREAS or ERROR_FOOTPRINT_VIOLATION
9. Checkpoint resumability -> ERROR_RESUME_CHECKPOINT_INVALID
10. Total distance computed -> reported in metadata.warnings if total > some-large-threshold

Pre-geometry validations (run before plan building):
- areas empty -> ERROR_NO_AREAS
- dock_pose outside any allowed area -> ERROR_DOCK_OUTSIDE_AREAS
- robot_geometry invalid -> ERROR_INTERNAL (Plan 05 already handles this)
- resume_from_checkpoint=true and any required .kv missing/corrupted -> ERROR_RESUME_CHECKPOINT_INVALID
- Working area entirely covered by obstacle (zero footprint-fittable area) -> ERROR_OBSTACLE_BLOCKS_AREA
- Working area too narrow for footprint anywhere -> ERROR_AREA_TOO_NARROW

Post-geometry validations (run on the constructed plan):
- Every waypoint footprint inside allowed area (1)
- No waypoint footprint intersects an obstacle (2)
- Outline offset is consistent (5)
- Path spacing matches `tool_width - strip_overlap` (6)
- Dock segments collision-free (8)
- Working-area mowing only (3)
- Navigation areas blade-off (4)

ERROR_OBSTACLE_OFFSET_FAILED is reserved for offset_polygon_inward returning a degenerate (empty / self-intersecting) result on an obstacle outline.

    **ValidatorPipeline:**
    - struct Validator { virtual std::optional<PlanError> check(const PlanContext&) const = 0; virtual const char* name() const = 0; };
    - PreGeometry validators (run before plan_builder; these gate plan building):
      - NoAreasValidator (areas empty -> ERROR_NO_AREAS)
      - DockInAreaValidator (dock_pose outside all allowed areas -> ERROR_DOCK_OUTSIDE_AREAS)
      - AreaWidthValidator (any working area with footprint-untraversable interior at any orientation -> ERROR_AREA_TOO_NARROW; only flagged when narrow_area_strategy=SKIP)
      - ObstacleCoverageValidator (any working area whose obstacles cover >=99% of fittable interior -> ERROR_OBSTACLE_BLOCKS_AREA)
      - ResumeCheckpointValidator (only run if goal.resume_from_checkpoint; reads each .kv via read_checkpoint_file; any missing/corrupt -> ERROR_RESUME_CHECKPOINT_INVALID)
      - ObstacleOffsetValidator (run offset_polygon_inward on every obstacle with the expansion inset; if any returns empty polygon -> ERROR_OBSTACLE_OFFSET_FAILED)
    - PostGeometry validators (run after plan_builder; these gate plan emission):
      - FootprintInsideAreaValidator (every waypoint -> footprint_inside_polygon against allowed area; failure -> ERROR_FOOTPRINT_VIOLATION, failed_validation_point=1)
      - FootprintDisjointObstaclesValidator (failure -> ERROR_FOOTPRINT_VIOLATION, failed_validation_point=2)
      - SegmentTypeInvariantValidator (UNDOCK only at indices 0-1; DOCKING at last index; MOWING_BOUSTROPHEDON only inside working areas; blade_enabled correlates per SPEC R-4 — failure -> ERROR_INTERNAL, failed_validation_point=3 or 4)
      - PathSpacingValidator (consecutive scan-line x-coords differ by tool_width-strip_overlap +/- 1mm — failure -> ERROR_INTERNAL, failed_validation_point=6)
      - DockSegmentsCollisionFreeValidator (UNDOCK + DOCK_APPROACH + DOCKING segments' footprints all clear — failure -> ERROR_FOOTPRINT_VIOLATION, failed_validation_point=8)
    - Pipeline: fail-fast; first non-nullopt result is returned.

    **OutlineGenerator (SPEC R-7, footprint-centric per SPEC R-6):**
    - generate_working_area_outlines(area_polygon, robot, outline_passes) -> std::vector<CoverageWaypoint>
      - For p in 0..outline_passes-1: inset_p = robot.outline_offset + robot.footprint.robot_width/2 + p * (tool_width - strip_overlap); call mowgli_geometry::offset_polygon_inward(area_polygon.points, inset_p); if result empty -> warning "outline pass p produced empty polygon, halting outlines for this area"; else emit CCW traversal with one waypoint per vertex; segment_type=OUTLINE_WORKING_AREA; blade_enabled=true; speed=mowing_speed; yaw at each vertex = atan2(next.y - cur.y, next.x - cur.x).
    - generate_obstacle_outlines(obstacle_polygon, robot, outline_passes) -> std::vector<CoverageWaypoint>
      - Same loop with negative inset (outward); segment_type=OUTLINE_OBSTACLE; rest identical.

    **BoustrophedonSweeper (SPEC R-8, footprint-centric, RESEARCH §3.3 algorithm):**
    - sweep(area_polygon, obstacles, mow_angle_rad, robot, narrow_strategy_callback) -> std::vector<CoverageWaypoint>
    - Steps:
      1. rot = pi/2 - mow_angle (rotate so strips run along Y)
      2. rotated_area = rotate_polygon(area, rot); rotated_obstacles = rotate each
      3. expanded_obstacles = offset_polygon_inward(o, -(robot_width/2 + outline_offset)) for each o
      4. AABB(rotated_area) -> [min_x, max_x] x [min_y, max_y]
      5. x_inset_innermost = robot_width/2 + outline_offset + (outline_passes-1)*(tool_width-strip_overlap); x_first = AABB.min_x + x_inset_innermost + (tool_width-strip_overlap)/2
      6. For x in x_first..AABB.max_x-x_inset_innermost step (tool_width - strip_overlap):
        - Compute y intersections of vertical line @ x with rotated_area edges (mark from_outer=true)
        - Compute y intersections with each expanded_obstacle (mark from_outer=false)
        - Sort by y; even-odd-fill pairing yields scan-segments; for each pair (y_lo, y_hi):
          - y_lo += y_inset (where y_inset = robot_length/2 + outline_offset + (outline_passes-1)*step - strip_outline_overlap, clamped >= safety_inset=0.01)
          - y_hi -= y_inset
          - if (y_hi - y_lo) < robot.footprint.robot_length: invoke narrow_strategy_callback(area_idx, segment, area, obstacles, robot) which returns either {} (SKIP), an extra outline pass, or a SPECIAL_PATTERN center-line; collect those waypoints; ALSO add metadata.warnings entry "narrow strip in area X handled via STRATEGY"
          - else: rotate (x, y_lo) and (x, y_hi) BACK to map frame (rotation by -rot); emit two waypoints (start + end); alternate direction per column index (boustrophedon: even cols low->high, odd cols high->low); segment_type=MOWING_BOUSTROPHEDON; blade_enabled=true; speed=mowing_speed; yaw = direction-of-travel.
    - Implementation note (RESEARCH §1): the rotation can use a 2x2 cos/sin matrix; no Boost needed for the rotation itself.
