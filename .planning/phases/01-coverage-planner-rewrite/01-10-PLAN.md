<objective>
Add `uint32 area_index` to `CoverageWaypoint.msg`, regenerate firmware/Go/TS bindings, and stamp the field in PlanBuilder for every waypoint emitted. This is half of the CR-01 fix (the planner-side / interface-side half). Plan 01-11 then consumes the field on the BT side.

Purpose: The verifier (`01-VERIFICATION.md`) found that R-9 (auto-rotate) and R-11 (resume-after-charging) both fail end-to-end because the BT cannot stamp the canonical per-area key into the Checkpoint it sends to the planner — `CoverageWaypoint.msg` has no `area_index` field. This plan introduces the field and stamps it server-side. Plan 01-11 will then replace `req->checkpoint.area_index = last_wp.sequence_id` with `last_wp.area_index` in `dispatch_checkpoint_write`.

Output: An interface-level extension that is build-clean across all four code-generation chains, with the planner already populating the new field for every waypoint.
</objective>

  PlanContext ctx = make_two_area_ctx(tmpdir_);
  PlanBuilder builder(ctx.robot, tmpdir_);
  ASSERT_TRUE(builder.build(ctx));

  std::size_t mow_for_a0 = 0, mow_for_a1 = 0;
