## Coordination Risks

**Cross-format compatibility between calibrate_imu_yaw_node writer and
new C++ parser:**

The new line-anchored C++ parser cannot read indented (nested) YAML.
Today `calibrate_imu_yaw_node.py` still writes
`{dock_calibration: {dock_pose_x: ..., yaw_sigma_rad: ...}}` via
`yaml.safe_dump` (lines 545-560) — the `dock_pose_x` line is indented
by 2 spaces. With the historic non-anchored
`std::string::find("dock_pose_x:")` parser this happened to work
because the substring search did not care about the indent. The new
parser anchors on `\n + key:` and rejects the indented form.

**Impact:**

- The C++ readers (`hardware_bridge_node`, `map_server_node`) on
  existing dock_calibration.yaml files will fall back to the ROS
  parameter (the documented "file missing" path) until the writer is
  migrated. That is a regression in dock-pose precision (config-file
  ~10° vs file-derived ~1°) but does not crash anything.
- The Python reader's regex tolerates leading whitespace and
  continues to read the legacy nested format unchanged.
- **Plan 02-03 must migrate `calibrate_imu_yaw_node.py` writer to
  flat key=value (no `dock_calibration:` top-level wrapper) for the
  C++ readers to start picking up file-based dock poses again.**

This is documented as a Known Stub for the verifier and as a
hand-off note to Plan 02-03's executor. Plan 02-04's
dock_scan_meta_loader is unaffected (writes flat from day one) — the
risk is bounded to the legacy file path.
