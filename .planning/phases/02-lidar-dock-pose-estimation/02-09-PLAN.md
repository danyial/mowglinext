<objective>
Resolve GAP-02 from `02-VERIFICATION.md` § "Build Gaps": `mowgli_lidar_docking`
fails to find the `kinematic_icp/pipeline/KinematicICP.hpp` and
`kiss_icp/core/VoxelHashMap.hpp` C++ headers because the upstream
`kinematic_icp` ROS package neither installs them nor `ament_export_*`-es
them, and `ament_target_dependencies(... kinematic_icp)` only propagates the
`kinematic_icp_ros` wrapper headers — not the cpp library headers our matcher
includes.

Plan 02-02 PROBE.md (lines 47-52) flagged this exact integration risk; Plans
02-02 and 02-04 ignored the warning and shipped the naive `ament` pattern,
which compiled cleanly on the macOS host (no actual CMake configure run) but
failed at the phase-end podman build.

This single-plan gap closure rewrites `mowgli_lidar_docking/CMakeLists.txt`
to use Path A from VERIFICATION.md ("Self-FetchContent + add_subdirectory in
mowgli_lidar_docking"), with one refinement: because the `kinematic_icp` cpp
top-level CMakeLists (`ros2/src/kinematic_icp/cpp/kinematic_icp/CMakeLists.txt`)
already does `include(kiss_icp/kiss-icp.cmake)` which `FetchContent_MakeAvailable`-s
kiss_icp, we do NOT need a separate `FetchContent_Declare(kiss_icp ...)` block
in `mowgli_lidar_docking` — `add_subdirectory(... cpp/kinematic_icp ...)` pulls
in kiss_icp transitively. We rely on EXCLUDE_FROM_ALL + a scoped binary-dir
name to avoid CMake target-redefinition conflicts when colcon builds
`kinematic_icp` and `mowgli_lidar_docking` in the same workspace.

Purpose: unblock R-2, R-3, R-7, R-8, R-12, R-13 — every requirement whose
gtest binary lives in `mowgli_lidar_docking`, `mowgli_behavior` (depends on
the `IDockMatcher` lib from this package), or `mowgli_simulation` (depends
transitively via launch files). After this plan executes and the operator
runs `podman build --target build`, the 13-package workspace builds green
and Phase 2 is ready for the Pi5 5-of-5 hardware UAT.

Output: rewritten `CMakeLists.txt` + a new regression smoke gtest that
guards against future "simplifications" of the linkage. No source files
under `ros2/src/kinematic_icp/` are modified.
</objective>

<decision_rationale>
**Path A** is selected per VERIFICATION.md § "Suggested fix paths".

- **Path A — self-add_subdirectory** (chosen): keeps `mowgli_lidar_docking`
  self-contained, no fork burden against PRBonn upstream, ~3-5 min added to
  the build. The kinematic_icp cpp top-level CMakeLists already pulls
  kiss_icp via `include(kiss_icp/kiss-icp.cmake)`, so a separate
  `FetchContent_Declare(kiss_icp ...)` in mowgli_lidar_docking would
  duplicate state and risk version skew. Instead, mowgli_lidar_docking does
  ONE `add_subdirectory` of the kinematic_icp cpp tree, which transitively
  pulls kiss_icp at the same pinned URL/version (v1.2.0).
- **Path B — patch the kinematic_icp submodule**: rejected. Would require
  changing `.gitmodules` to point at our fork plus carrying a forever-diff
  against PRBonn. Local podman builds before push (per memory rule
  `feedback_local_build_before_push.md`) become a fork-maintenance burden.
- **Path C — vendor kiss_icp / kinematic_icp headers** into
  `mowgli_lidar_docking/third_party/`: rejected. Loses upstream fix tracking
  for both libraries, and the matcher already needs the kinematic_icp
  pipeline LIBRARY (not just headers) so we'd be vendoring sources that
  must compile against the same Sophus/Eigen toolchain used by the rest of
  the workspace.

**Risk mitigation for Path A**: CMake target-redefinition. Both
`kinematic_icp` (the ROS package) and `mowgli_lidar_docking` (this fix)
will trigger `add_subdirectory(... cpp/kinematic_icp)` from different
parent CMake contexts during a single colcon workspace build. Each colcon
package configures + builds in its OWN build directory under
`ros2/build/<package>/`, so target names like `kinematic_icp_pipeline`
exist independently in each build tree — there is no cross-package
redefinition. Within `mowgli_lidar_docking`'s own build tree, we use:

1. `EXCLUDE_FROM_ALL` on the `add_subdirectory` call so kinematic_icp's
   `add_executable(kinematic_icp_offline_node ...)` etc. (declared in
   `ros2/src/kinematic_icp/ros/CMakeLists.txt`, NOT in the cpp tree we
   pull in — verified during plan authoring) do not get added to our
   default ALL target. The cpp tree only declares libraries
   (`kinematic_icp_pipeline`, `kinematic_icp_registration`,
   `kinematic_icp_threshold`, plus the kiss_icp libs), so this is mostly
   defence-in-depth.
2. A scoped binary-dir name `kinematic_icp_cpp_for_mowgli` that prevents
   collision with any other `add_subdirectory` of the same source tree
   that may exist in our own build directory in the future.
</decision_rationale>
